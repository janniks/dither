| **N1** | `packages/cli/src/collection-paths.ts:50-63` (`grantsCover`)                                          | **`messages/**`does NOT match bare`messages`** under standard picomatch semantics. A plugin granted `["messages/**"]`and writing`collection: "messages"`is rejected at promote with a "not granted" error. Silent UX regression vs. the flat collection model. Spec at`specs/nestable-collections.md`doesn't address this. Either: (a) make`grantsCover`treat`X/**`as also covering bare`X`, or (b) document that authors must declare both `["messages", "messages/**"]`. No test covers this case.                                                                                                                                                                                                                       |
| **N2** | `packages/cli/src/plugin-install.ts:90-98` (`resolveAllowList` rewrite)                               | **Manifest-as-ceiling guardrail removed.** Explicit `--allow-collection`/`--allow-net` flags now win outright with **no subset check**, **no pattern validation**, and **no charset check** on user-supplied values. A typo'd `--allow-collection ../system` or `--allow-collection ""` is silently persisted into the grants file. The same is true for `--allow-net`. Loss of property: previously, the manifest+CLI combination was a sandwich (declare ≥ grant); now the user is solely responsible. The spec dresses this as a "principled simplification across grant kinds" but the body is `provided ?? declared`. Add a `validateGrantPattern` step at install (and on every per-run override) before persisting. |
| **N3** | `packages/cli/src/plugin-install.ts:118-119`                                                          | **Manifest grant patterns are never validated at install time.** `parsed.manifest.collections` strings flow straight to `resolveAllowList` without `validateCollectionPath`-style screening. A manifest declaring `collections: ["../*"]` or `collections: [""]` installs cleanly. Empty-string globs in picomatch have surprising semantics.                                                                                                                                                                                                                                                                                                                                                                              |
| **N4** | `packages/cli/src/collection-paths.ts:31` (`validateCollectionPath` segment regex)                    | **Hidden-file segments (`.git`, `.ssh`, `.DS_Store`) pass.** Combined with `picomatch({ dot: true })` (`:44`), a grant of `**` will match `.git/**`. If a user ever points `~/.dither/entries/` at a directory inside a git repo, a plugin with `**` could shadow VCS metadata. At minimum reject leading `.` per segment, or document the risk.                                                                                                                                                                                                                                                                                                                                                                           |
| **N5** | `packages/cli/src/plugin-run.ts:57-65` (`extractField`) — was already cited as M5 in the prior review | The hand-rolled YAML regex is now **load-bearing for security**. The promote gate at `:233-234` trusts whatever this function returns. A frontmatter line like `collection: "messages/foo" # comment` parses imperfectly (greedy `[^"\n]+` swallows past the closing quote, optional trailing `"?` backtracks). The new validator catches the resulting garbage by charset, but the error message embeds the raw value (potentially with control characters/ANSI). Bumped from "should-fix" in the prior review to **must-fix** because the security gate now depends on it.                                                                                                                                               |

| **N6**  | `packages/cli/src/plugin-run.ts:223-238`                                     | **Order of checks in promote leaks plugin-name info.** `source !== opts.name` is checked before `validateCollectionPath`. The error at `:226` interpolates `source` unescaped. A malicious plugin can craft `source: <victim>` + a malformed `collection:` to produce an error message confirming or denying which other plugin is installed. If the goal is "collections are directories, not files", the suffix check is theater (segment regex already permits files-shaped names like `archive.md` as a _segment_). Either drop the check or apply it consistently. |
| **N8**  | `packages/cli/src/collection-paths.ts:27-35`                                 | **`...` and `....` segments pass.** The validator rejects literal `..` only. Validate patterns at install.                                                                                                    |
| **N10** | `packages/cli/src/plugin-run.ts:94-96`                                       | **Grants file loaded without runtime schema validation.** A corrupted grants file with `collections: [42, null]` reaches `picomatch(42)` and throws a generic `TypeError` mid-promote.
