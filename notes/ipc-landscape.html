dither — IPC & process landscape

Single CLI binary. One long-lived daemon. Sandboxed Deno subprocesses for plugins. The filesystem is the wire — every IPC primitive is a file (or signal).

Processes

CLI dither <cmd>

Short-lived. Reads qmd directly for search/get. Sends requests to the daemon for plugin and index work. Auto-spawns the daemon if it's not running.

daemon dither daemon run

Long-lived. Owns scheduler, watcher, refirer, reconciler, plugin host. Heartbeats status.json at 1 Hz. Writes dither.pid at startup; verifies own identity before unlinking it on shutdown.

plugin Deno subprocess

Spawned per run by the daemon. Sandboxed via Deno flags derived from grants (--allow-{read,write,env,net}). Writes markdown into runs/<runId>/; daemon promotes on clean exit.

IPC primitives

nameon diskscopeshape & lifecycle
Lock locks/<name>.lock per-name O_EXCL create; body is holder PID. Acquire/release; stale (dead PID) is reclaimed. Two surfaces: acquire(name) for plugins / daemon-start, acquireTheme(theme) for qmd-{download,index,embed}.
Kick kicks/<plugin>.json per-plugin CLI writes one to request a run. Daemon scans on SIGHUP and consumes (delete on fire). Latest-write-wins.
Inbox inboxes/<plugin>.ndjson per-plugin Watcher appends NDJSON rows (path + mtime). Fire start atomically renames inbox → inflight and reads it. Failure paths restore inflight → inbox (at-least-once).
Refire refires/<plugin>.json per-plugin Reschedule state ({fireAt, attempts, suspended}). Refirer holds one setTimeout per row; chunks past 32-bit max.
Marker markers/<name> daemon-global Zero-byte presence flag. Cheap per-iteration check via existsSync. Two flavors today: request (needs-reindex — write, consume, clear) and state (embed-disabled — write, persist, explicit unlink).
Run-log run-log.jsonl, history/<runId>/events.jsonl global + per-run Append-only JSONL. Followers poll + stat (rotation-safe via dev/inode). Per ADR 0001 the seam is one module, the on-disk layout is two paths.
Snapshot status.json, env.json, config.json, dither.pid, history/<runId>/{manifest,result}.json global / per-run One file replaced wholesale on each write (tmp + rename for atomicity where readers race).
Signal SIGHUP / SIGTERM / SIGINT / kill(pid, 0) process SIGHUP = reload config + grants + refires + reconcile. TERM/INT = graceful shutdown (30 s child-drain). kill(pid, 0) = liveness probe (no signal sent).

The "kick-and-watch" pattern

Many CLI commands follow this shape: (1) snapshot the global run-log byte offset, (2) write a request file (kick or marker), (3) send SIGHUP, (4) follow the log from the pinned offset until a terminal event arrives (reconcile-done, run-close, failure). Pinning the offset closes the race where the daemon emits the event before the follower opens the log. daemonClient.triggerAndWatch() is the canonical implementation; watchReconcile yields a filtered DaemonEvent union and terminates on reconcile-done.
